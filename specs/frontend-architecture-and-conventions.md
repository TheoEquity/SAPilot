# 前端开发规约

本文规定前端开发的职责、文件归属和维护方式。公共变更按[开发流程](development-workflow.md#公共变更与已有授权)处理。

高层模块与依赖见[工程架构概述](engineering-architecture.md)。下文的文件示例、状态、样式和检查要求属于开发细则；接口字段与请求响应由后端 Python 模型与路由定义，文档和前端类型由工具生成。

## 层次与文件归属

| 层次 | 职责与边界 |
| --- | --- |
| 路由与布局 | `web/src/app/` 放页面入口、导航、权限入口与服务端初始加载，组合就近业务实现 |
| 业务模块 | 对应业务的状态、请求、规则和界面，默认跟随现有业务目录 |
| 通用界面组合 | `web/src/components/` 中的跨业务页面容器、表格和表单组合，有实际共享需求后提取 |
| 基础组件 | `web/src/components/ui/` 处理通用显示与交互，不感知 Bot、Skill、知识库，不请求业务接口 |

页面组合业务实现，业务实现使用通用组合与基础组件；基础组件不反向依赖业务模块。新增与拆分文件按以下顺序确定归属：

1. 已有业务跟随现有模块，就近放私有组件、Hook 和转换函数；简单页面在对应路由目录组织，不按行数强拆。
2. 跨页面复用先查已有业务目录，避免平行实现。`components/chat/` 是现有聊天业务目录，不因位于 `components/` 就成为通用基础组件。
3. 有实际共享需求时，通用界面归入 `components/`，业务实现归入对应业务模块。共享实现不依赖 `app/` 的路由内部文件，相关类型与配置处理随实现提取；同一路由业务目录内的私有文件可以相互引用。
4. 只有跨页面业务需要独立共享目录、且现有业务目录不适合作为归属时，才考虑 `features/<业务名>/`；具体任务说明迁入文件、调用方和依赖方向。

不为目录整齐批量迁移，也不要求每个模块建立相同文件集。

## 文件归属示例

| 模块 | 文件与职责 |
| --- | --- |
| Skill 编辑 | [skills/](../web/src/app/workspace/bots/[botId]/skills) 中的 `skill-editor.tsx` 组合界面，`skill-editor-fields.tsx` 承担表单区域，`use-skill-editor.ts` 协调编辑，`skill-config.ts` 构造配置 |
| Bot 保存 | [bot-config-updater.ts](../web/src/app/workspace/bots/[botId]/bot-config-updater.ts) 复用现有 API 保存编排配置 |
| 聊天与附件 | [components/chat/](../web/src/components/chat) 保留展示和输入组件；`use-chat-messages.ts`、`use-chat-attachments.ts` 承担对应逻辑 |
| 请求与生成代码 | `web/src/lib/api/client.ts`、`server.ts` 为现有请求入口；`web/src/api/` 为生成接口代码 |

配置转换尽量保持为不依赖 React 和网络的函数。普通保存与画布快捷保存共享构造函数，但保留各自的触发、校验、去重和反馈语义，不借拆分统一行为。

## 组件与样式

- 编写前查找现有组件及调用处，核对 Props、事件、变体与交互状态；保留现有 UI 和组件体系，新增界面优先组合已有组件，暂不引入网上组件。
- 沿用 Tailwind、主题变量、`cn()` 和已有 `cva` 变体；局部差异优先使用现有扩展点。全局 CSS 保留主题与基础规则，复杂局部样式按需使用 CSS Modules，运行时坐标等允许必要动态样式。
- 公共范围按实际调用者、样式影响和对外用法判断；不通过复制公共源码、全局选择器或覆盖内部结构绕过公共变更边界。
- 核对明暗主题、相关窗口尺寸、文本溢出、loading、disabled、错误状态，保留语义控件、Label、键盘、焦点和可访问名称。
- 不批量引入未用示例；性能结论依据实际加载与页面数据，不由文件变少或拆分完成推断。

## 状态、表单与副作用

- 每份编辑草稿有明确持有者：服务器快照沿用现有 Provider，表单沿用 React Hook Form 与 Zod，画布草稿由业务编辑器持有，临时交互留在相关组件。
- 派生值尽量计算，避免多份可写副本互相覆盖，或用多个 Effect 同步同一含义的数据。沿用现有 Context 和表单能力，不因整理增加状态库。
- 请求、订阅、计时器、WebSocket、预览 URL 明确生命周期与清理，按风险检查对象切换、失败和迟到响应。
- 编辑逻辑协调输入、校验、pending、成功、失败、刷新与草稿重置；保留不同保存入口各自语义。
- 保留 Server / Client Component 边界，交互部分按需使用客户端组件，不为引用方便改整棵页面树。

## 接口与验证

优先复用现有浏览器、服务器 API 入口，按[接口契约规约](api-contract-conventions.md)维护类型、生成与 WebSocket 边界；已有直接请求按任务处理。用户可见新文案沿用 next-intl，SAP 标识保留原文。前端显隐不能替代后端授权，密钥与私有配置不进入浏览器代码、公开环境变量或日志。

实施前核对最新源码、未提交改动、相关页面和调用方，记录必要界面基线。按影响检查操作、主题、键盘、表单载荷、字段保留、保存回读、对象切换与资源清理；聊天和附件补对应上传、发送、事件、停止、引用及历史检查。

执行适用的类型、lint、格式检查、构建及必要本地交互验证；先核对脚本副作用，不直接全仓自动修复或覆盖环境。类型或构建通过不能代替视觉、浏览器生命周期和完整问答验收，交付保留未验证项。
