# 后端开发规约

本文规定后端开发的职责与维护边界。公共变更遵循[开发流程](development-workflow.md#公共变更与已有授权)，领域与安全要求见[项目背景](../docs/SAPILOT_PROJECT_CONTEXT.md)。

高层模块与依赖见[工程架构概述](engineering-architecture.md)。下文规定代码归属、执行边界和检查要求；接口定义与自动汇总见[接口规约](api-contract-conventions.md)。

## 职责与文件归属

沿用 FastAPI、Celery、模型调用、检索和存储体系，优先复用现有能力，不为分层新增框架、统一基类或没有实际职责的转发层。

| 位置 | 维护职责 |
| --- | --- |
| `aperag/views/` | 协议参数、身份取得、Service 调用与协议响应，业务规则交由业务层组织 |
| `aperag/service/` | 业务规则、资源权限、事务协调和流程组织，区分业务协调与具体协议发送 |
| `aperag/agent/` | 意图路由、会话、历史、消息队列、事件与格式化能力 |
| `aperag/flow/` | 传统 Flow 执行与检索等可复用能力节点，不等同于全部 Agent Skill 执行 |
| `aperag/llm/`、`aperag/mcp/`、`aperag/docparser/`、`aperag/index/` | 模型、工具、解析和索引能力 |
| `aperag/db/`、`aperag/objectstore/` | 查询、持久化与对象存储，保留已有用户过滤和事务语义 |
| `aperag/tasks/`、`config/celery_tasks.py` | 后台任务、调度衔接和任务状态处理 |

具体修改先查调用者，不以文件行数或目录名称决定拆分。

## 执行与渠道边界

- Agent Skill 与传统 Flow 保留各自的执行语义，不因目录或名称相似而合并。
- 意图路由、上下文准备、Skill 执行、附件和会话历史按职责组织，复用会话、队列和事件能力。
- Web 与钉钉复用业务操作，渠道负责输入输出差异，不另建问答主流程。

## 开发要求

- 修改前检查实现、调用者、配置和相关测试；能力适用时按原契约复用，不复制公共实现绕过变更判断。
- 后端核对 Bot、会话、知识库、文件、模型和工具的用户访问范围，前端校验和传入 ID 不能代替授权。
- 复用异常、审计、数据访问与事务入口，保持关联写入的必要原子性，不顺手改变提交、回滚和任务触发时机。
- 明确请求、凭据和会话状态归属，避免共享可变配置造成跨用户覆盖；Redis 历史存在不代表全部状态可恢复。
- 沿用命名和类型约定，明确关键参数与返回结构；日志保留必要标识，避免输出凭据与完整私有资料。
- 接口和生成类型按[接口规约](api-contract-conventions.md)维护；字段能够保存不等于已经参与执行。
- 纯结构整理保留路由顺序、模型参数、Prompt、资源回退、流式事件和执行语义，行为调整另行说明并验证。

## 问答与后台摄取

接口、Service、模型/工具与 worker 的关键事件、耗时、异常依据和关联上下文遵循[全栈日志规约](logging-and-diagnostics.md)。业务日志统一使用 Python 标准库 `logging`，各模块用 `logging.getLogger(__name__)` 获取 logger，业务字段通过 `extra` 传入；统一配置格式、级别与输出，业务模块不另装 handler 或用 `print` 代替。调用链复用 OpenTelemetry 和 Langfuse，保留 API 到后台任务的关联，不将日志或观测故障升级为业务失败。

问答按接入、配置、路由、执行、返回与保存组织。文档摄取沿用文档服务、reconciler、Celery 和索引实现，通过上传确认、后台调度、解析、索引与状态更新协作；耗时解析和索引留在后台。

任务修改核对失败、取消、重试、重复执行和状态转换；按实际证据决定是否调整机制，不预建锁、重试或新调度框架。相关实现见[摄取与索引说明](../docs/zh-CN/design/current/document-ingestion-and-indexing.md)。

## 验证与交付

按风险复用现有 Ruff、mypy、pytest 和本地运行入口，区分历史基线与新增问题。公共路径检查调用者、权限与异常；会话和流式修改核对事件、取消、错误、保存及必要恢复；数据写入核对事务与状态；摄取、检索与回答按项目背景分层验证。

开发与日常验证在本地进行。完整模型聊天、并发隔离、状态恢复和 SAP 效果需要对应运行证据；静态核对、替身测试和历史记录仅支持各自检查范围。交付保留实际结果、未验证项及下一步负责人。
