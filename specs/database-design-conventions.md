# 数据库设计与迁移规约

本文规定数据库设计与维护方式。公共变更按[开发流程](development-workflow.md#公共变更与已有授权)处理；设计、迁移代码、本地验证和目标库执行分别核对授权范围。

## 文件归属

业务模型主要位于 [aperag/db/models.py](../aperag/db/models.py)，迁移位于 [aperag/migration/versions/](../aperag/migration/versions)，[迁移环境](../aperag/migration/env.py)读取模型 metadata；查询与事务复用 [Repository](../aperag/db/repositories)。

## 表与字段

| 设计对象 | 要求 |
| --- | --- |
| 表职责 | 明确业务对象、归属和生命周期，先判断是否复用现有表，避免同一事实重复维护 |
| 命名与主键 | 新名称用清楚的 `snake_case`，沿用适用模块的 ID 策略并说明生成方；不批量重命名或更换标识 |
| 类型与长度 | 按业务范围确定；精确数值用适当定点类型，SAP 编号等保留字符串语义和前导零 |
| 空值与默认值 | 区分未知、不适用、空串和零，说明默认值含义、维护方及旧记录处理 |
| 关联与归属 | 引用字段类型、长度和语义匹配，说明物理外键或应用维护关系、删除行为及用户或资源过滤 |
| 时间与状态 | 明确 UTC / 时区、创建更新删除时间的维护方、合法转换及恢复清理规则，不凭字段名推断自动更新 |
| 约束与索引 | 由业务确定非空、唯一范围、检查和关系完整性；按实际过滤、关联和排序设计索引，避免重复 |
| JSON 与版本 | 核心查询、关联和约束信息优先独立字段；灵活配置按需求选择，写清版本维护与使用方，不把版本字段等同并发保护 |
| 敏感数据 | 明确读写范围和必要保护，样例和日志不包含密钥或完整私有资料 |

分别核对应用 `default` 与数据库 `server_default`，以及插入与更新时间维护；变更时核对模型、迁移和目标库结构。

## 软删除与唯一性

使用软删除时，明确有效记录条件、普通查询过滤、历史唯一范围、名称复用、恢复冲突，以及关联数据和物理清理规则。不能仅凭联合唯一约束包含 `gmt_deleted` 就断言有效记录唯一，须核对 NULL、其他可空字段及目标数据库的实际约束语义。

## 结构变更材料与执行范围

新增或修改表、字段、索引、约束、默认值、关系和删除策略时，说明用途、归属、生命周期、关联、唯一范围、主要查询与索引依据；已有表补充前后差异、旧数据兼容或回填、受影响 Service / API / 任务及其他使用方。

| 字段 | 含义与单位 | 类型与长度 | 可空性及 NULL 含义 | 默认值与维护方 | 约束与关联 | 敏感性 |
| --- | --- | --- | --- | --- | --- | --- |
| 按实际设计填写 | 明确取值语义 | 按业务范围 | 说明理由 | 区分应用与数据库，说明更新规则 | 明确唯一范围 | 明确读写范围 |

字段与接口不要求机械一一对应，但映射必须明确。普通业务通过既有入口增删改记录不全部属于结构变更；批量修复、回填和删除仍须明确范围。代码修改获准不自动代表任意目标库执行获准，核对现有授权是否已涵盖环境和操作；生产操作继续遵守[项目安全要求](../docs/SAPILOT_PROJECT_CONTEXT.md#7-安全要求)。

## 迁移与验证

- 模型变更配套 Alembic 迁移，不先手改共享环境再补记录，不擅自修改已被其他环境使用的历史 revision。
- 自动生成仅作候选，人工检查无关差异、删除重建、约束、默认值与数据处理；根据表规模评估必要的锁、时长和实施安排。
- 非空、唯一约束或类型变更前检查旧数据的空值、重复、范围和转换条件；回填需要业务依据。
- 在本地隔离库验证空库建库、代表性旧版本升级及相关查询、写入、删除、恢复；默认值、时间、唯一性和关系变更覆盖相关写入及必要并发异常行为。
- 说明回退或恢复方式；`downgrade()` 存在不代表被删除或覆盖的数据可恢复。必要备份验证可用，不在用户数据上试验回退。
- 交付记录模型、迁移、实际结构及接口核对结果，分别说明已执行和待验证的升级、恢复或性能检查，不把生成成功称为迁移验收。
