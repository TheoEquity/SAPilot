# 第四阶段：图片与证据链修复复验

日期：2026-10-31。目标是接通真实图片输入，再修复跨页证据缺口、漏答及输出中断，使用原七份材料和冻结的 38 题复跑；不扩展到百份，不改架构总纲，不修改题目或评分标准。

阶段范围按用户最新决定调整：本阶段以流程跑通、工程质量可接受、基本功能实现为目标，继续使用现有七份材料，暂不扩展到 100 份文档。题集成绩和失败原因保留作为后续质量优化依据，达到八成及规模/容量验收暂不作为本阶段结项门槛；影响基本功能或工程稳定性的缺陷仍需处理。此范围调整不改变下文实测结果，也不直接认定工程验收已全部通过。阶段计划见[整体开发计划](development-roadmap.md)。

## 修复范围与依据

- 图片解析：镜像已有 Tesseract 和中文语言数据；缺 Paddle 配置时原解析器直接失败。现保留 Paddle 路径，并复用本机 Tesseract 回退，不引入新 OCR 服务。
- 图片输入：原流程只给模型文件描述，且预检绑在固定 Skill ID 上。现在读取当前用户、当前聊天的真实附件字节，取得实际视觉观察用于正常路由；各图分别做图向量检索，保留候选和歧义，不强制选第一项。
- 源图核验：知识库上下文可显式指定已返回的图资产，经过用户、集合、文档、删除态和资产白名单校验，再用真实像素核验；Word 无扩展名资产根据实际图片字节识别格式。用户输入图与源图观察分别标注。
- 完整原文：现有 parsed.md 保留了 REPORT 连续执行、评估阶段新增记录等必要内容。MCP `search_collection` 增加受限同文档全文、相邻物理页和显式续取，保留原文顺序、分页与来源，未为题集写死 FAQ 或页码。
- 排序：避免全文原分数与向量相似度直接比较，并保留按通道请求的候选。固定 REST 诊断与 Agent 实际工具查询仍分别解释。
- 输出中断：从旧实际 Langfuse 观测确认多题 `finish_reason=length`，而服务直接结束。现在暴露 SDK 的真实结束原因，最多续写一次且禁用新工具；四轮工具预算耗尽时，基于已取证据生成一次正式答案，避免只返回检索计划或 `No response generated`。再次超限明确报未完成，正常 stop 不额外调用模型；仅输出最后一条正式答复，避免拼接前序检索计划。
- 图片出处：检索结果明确提供零基 `page_idx`、一基 `physical_page` 和完整图片 URL。最终答案只按真实、唯一且与已有范围一致的引用补齐图片来源；同名页图或来源冲突不猜测文档。纯视觉检索也纳入有效检索通道判断。
- 通用回答要求：核对全部条件和分支、必要时读完整上下文和原图，不从局部未命中推断全文不存在，不把静态表达式当作运行验证，不让长篇检索过程挤占正文。

图片说明的兼容链路保留：传统非视觉 Flow 与预览依赖已有 vision-to-text 描述，本轮未采用全局删除该路径的方案。视觉节点另补真实 SOURCE 文档关系，避免底层序列化将顶层文档标识写成字符串 `None`；嵌套原始 metadata 中真实标识仍在，不能据顶层错误推断之前所有图片查询都无法关联。

## 模型、集合与对照边界

复用已批准的百炼服务和现有适配，真实合成图片调用验证后注册 `qwen3.8-flash`（视觉生成）及 `qwen3-vl-embedding`（实测 2560 维）。使用独立修复集合 `cole544d1171ec489e5` 摄取相同七原件字节，保留旧 `text-embedding-v4` 基线集合，未混用两种向量空间。

本次同时调整了代码、模型、集合嵌入及输出预算（8192）。另修复已配置温度未透传到 SDK 请求的问题，并为 `qwen3.8-flash` 使用已验证的 `enable_thinking=false` 直接回答模式；其他模型选项不变。该模型思考模式默认行为与参数见[百炼官方文档](https://www.alibabacloud.com/help/en/model-studio/deep-thinking)。测试 Bot 的通用检索提示同步到已修复的通道排名合并方式，删除旧的“必须分两次查、异源分数混排”指导及重复集合展示；未注入题目标准答案、指定 FAQ 或页码。

新旧成绩可比较实际系统结果，不能把改善全部归因于某一处代码。正式运行逐题记录实际索引状态、并发、首字及总耗时；预检与正式题次分开。中间文字 14 题与图片 6 题的原答、失败和资源独立保留，不能挑选其中最好结果拼成最终成绩。

## 显示修复与仍待解决的问题

首轮图片 01/02 找到来源后只输出普通 `asset://` 链接，前端不会直接展示。现仅将与真实引用及来源范围一致的链接转换为内联图片；同名资产、参数冲突、引用文本与 metadata 来源冲突均不猜测。普通 HTTPS 文档链接及已有完整图片 URL 保持原行为。

38 份原答离线回放均幂等，原答和分数 SHA 未改：图片 01 新增两张可核验图片；图片 02 的来源证据不足，链接改为未确认，仍无图片，不能称两题均解决。回放中 10 条实际渲染资产均授权 GET 成功，SHA 与已核原件资产一致。随后只对原图片 01 做一次实际回归，内联原图下载 SHA、像素及 Max 物理 27 页上图位置匹配，独立判为 PASS；该单题结果不替换原整套的 7/12。

以图检索的纯向量通道仍弱：五道唯一原图题实际 Hit@1/@3 均为 1/5；其余四题未完整暴露 top5，@5 保留未知。混合视觉观察与文字检索的正确来源为 5/5，这不等于纯图片向量召回通过。

主要剩余错误包括图中文字 `9C` 读成 `9G`/`9I`、跨页 FAQ 续文归属错误、条件与图组关系漏答、局部截图与历史案例边界遗漏，以及材料完整范围审计能力不足。全量上下文能读取，不等于这些语义错误已修好。具体逐点证据见私有 `text/scores.json` 与 `multimodal-rerun/scores.json`。

图片 03 的原 PNG 及 Max 42 页用既有 ImageParser/Tesseract 实测，没有正确提取出关键 `9C`；当前 query 已摄取 OCR 与重跑结果一致。因此未把“附加既有 OCR”冒充这处识别错误的修复，也未将标准答案写入上下文。窄排查及补充回归另行保留。

针对跨页题 MAX03，进一步核验确认不是丢页、乱序或截断：原 PDF、parsed.md 及真实工具上下文均保留 63–65 页正确顺序，之前缺少明确的续文边界。MCP PDF 上下文现只按 native 正文中可靠的编号节标题、FAQ 编号及问题正文增加“续上页／新条目”标识，并注明这是系统标识而非原文；OCR、目录或缺乏可靠标记时不推断。原文、索引、分页 offset 不改，另保留可逆的原文字符及显示标记映射。

真实 6 个页条目重放核对：64 页上方续 0012、下方新 0013，65 页上方续 0013；移除系统标记后与原返回逐字一致，分页参数不变。新增跨页、无标记回退及 48000 字符续取回归通过。加载后只补跑原 MAX03 一次：71.31 秒 STOP、历史双保存；阶段入口和前后依赖已正确，旧的归属硬错未再出现，独立判为 **4/5 FAIL**。仍缺截图与各自方案的对应说明，实际工具没有请求源图，不能以核心文字关系正确替未回答的图组点补分。首轮该题 2/5 及整套成绩保持不变。

同域 `qwen3-vl-plus` 的限额能力探测未取得有效视觉输出：仅启动首张独立进程，外层超时后结束该进程，实际供应商调用是否发出未知；后两张未发送。没有据此得出识别能力或生成延迟结论，也未注册或切换共享模型配置。

MCP 的实际源图读取有独立成功 span 和完成日志，可按文档、图片数量及工具执行窗口关联；与聊天 trace 尚未完全贯通，SDK 工具输出只保留前 200 字符，完整视觉观察文本无法从这批观测恢复。不能据 URI 或模型自述认定已看图，也不能用工具结果替最终答案补分。
