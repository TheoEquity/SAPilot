入口为 `.github/workflows/test-ci.yml`。向 `test` 推送、或创建/更新目标为 `test` 的 PR 时自动运行，一个 Ubuntu job，最长 15 分钟，同一分支或 PR 的新运行取消旧运行。工作流仅有仓库读取权限，不使用模型、知识库或部署凭据，不使用 `pull_request_target`，不部署、不自动批准或合并 PR。其他分支本次不启用这套 CI，没有恢复归档的上游工作流。

| 检查 | 依据与范围 |
| --- | --- |
| Python 静态检查 | 按既有 Ruff 配置检查 `aperag/` 及接口导出脚本，拦截未定义名称、未用 import、import 顺序等错误 |
| 前端类型 | `yarn --cwd web typecheck` 检查整个前端 TypeScript，禁止将类型失败当作交付通过 |
| 前端 lint 与 UI 依赖边界 | 沿用 Next/ESLint；为基础 UI 增加业务路由、业务 API 别名导入限制，对应前端规约的依赖边界。此规则只覆盖明确列出的导入路径，不宣称完整理解所有业务依赖 |
| 契约与行为回归 | 原 `tests/contract/`，覆盖保存字段、接口导出、取消、输出完成、日志和视觉权限等；不启动真实服务 |
| 前端关键回归 | `yarn --cwd web test:ci` 自动发现现有 `.test.cjs` / `.test.ts`，运行聊天、标题、日志和 Mock 测试 |
