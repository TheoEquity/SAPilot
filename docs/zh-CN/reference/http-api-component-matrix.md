# SAPilot HTTP 接口与前端调用定位表

> 状态：2026 年 10 月 29 日当前工作区的静态盘点。主说明见[接口、组件与配置字段盘点](api-component-config-inventory.md)。本表仅定位源码关系，不表示接口已运行、载荷一致或调用分支可达。

## 范围与计数

- 主 OpenAPI 为 127 个 HTTP 操作，生成 SDK 也为 127 个操作，方法与路径相对应。
- 沿 app.py 及 include_router 静态展开得到 137 个 HTTP 装饰器操作，包含健康检查、独立 /v1 和 dev 测试接口；另有 1 个 WebSocket。二者 HTTP 并集为 138 行。
- 126 个主定义操作能找到同方法/路径实现；另外 1 个是明确标注 Doc Only 的 /agent/message。路径对应不等于字段、错误码、分页和鉴权语义相同。
- TypeScript AST 找到 147 个 SDK 源码调用点，涉及 97 个方法；30 个方法没有找到前端直接调用，不能据此推断无用。MCP、其他客户端、动态访问或未被扫描的外部调用不在该数字内。
- OAuth 工厂按条件挂载的子路由、FastAPI 自动文档路由、MCP 协议内部工具未展开为这里的 HTTP 操作数。源文件中的条件挂载也不等于运行环境实际启用。

扫描不导入后端应用、不启动服务、不执行生成覆盖。前端扫描排除生成目录，列出的调用点不包括注释；服务端组件通过 getServerApi 的调用也计入。动态别名和间接调用可能无法静态解析。“未发现”仅表示本次搜索边界。

后端请求/返回注解供定位，装饰器 response_model、函数分支与实际序列化仍需结合源码查看；依赖栏只展示函数体中可见 Depends，不代表完整授权审计。直接 fetch、下载 URL 和 WebSocket 另见主说明。
